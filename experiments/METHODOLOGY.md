# Methodology: identifying experiments and reporting them

How every experiment run against [`HYPOTHESES.md`](HYPOTHESES.md) is named,
how the code it ran is pinned, and what the report written after it must
contain. `HYPOTHESES.md` fixes *what* is tested and *how it is judged*; this
file fixes *how each attempt is recorded*, so that any number quoted later can
be traced back to the hypothesis it was meant to test, the code that produced
it, and the report that interpreted it.

Why each rule is what it is, and which experiments ran under it, is in
[`DECISIONS.md`](DECISIONS.md): a numbered, dated log of every decision that
shapes what an experiment tests or how it is read.

## Identifiers

Three things get an ID: the experiment, the run, and each algorithm. They nest:
an experiment is made of one or more runs, and each run executes one or more
algorithms.

| ID | identifies | form | example |
|---|---|---|---|
| **Experiment ID** | one attempt to test one hypothesis | `H<n>-E<nn>` | `H1-E01` |
| **Run ID** | one invocation of the harness, i.e. one results directory | `<UTC timestamp>_<name>` (from `provenance.Run`) | `20260926T081500Z_h1` |
| **Run key** | one arm on one dataset with one seed -- a *run* in the sense of `HYPOTHESES.md`, *Terms* | `<run ID>/<arm>/<dataset>/s<seed>` | `20260926T081500Z_h1/nsga2_sparse/eodata/s2022` |
| **Algorithm ID** | one arm as exactly executed: code and configuration | `<arm>@<code>#<config>` | `nsga2_sparse@a1b2c3d+9f8e7d6#4c1a` |

`HYPOTHESES.md` uses *run* for one arm x dataset x seed. That meaning is kept:
the **run key** is its identifier. The **run ID** identifies the invocation that
produced a batch of them, because that is the unit the harness writes to disk.

### Experiment ID

* `H<n>` is the hypothesis number from `HYPOTHESES.md`. `E<nn>` counts attempts
  at that hypothesis, from `E01`, in the order they are started.
* **An ID is never reused.** An experiment that crashes, is aborted, or is found
  afterwards to be invalid keeps its ID; the next attempt is `E02`. The count of
  attempts is itself part of the record -- five attempts before a clean result
  is information a reader needs.
* **H2 and H3 are one experiment** (see *Why this order* in `HYPOTHESES.md`), so
  their joint experiment carries both numbers: `H2H3-E01`. It gets one report,
  which states a verdict for each hypothesis separately.
* **H5 and H6 reuse the runs behind H1-H4.** Their experiment IDs are their own
  (`H5-E01`, `H6-E01`); the report lists every run ID it draws on, including
  those first produced under another experiment.
* A run that serves no hypothesis -- a smoke test, a timing probe, a debugging
  session -- gets no experiment ID and is never cited as evidence. Its run ID
  still exists, from `provenance.Run`, so it can be found and deleted.

### Run ID

Generated by `provenance.Run` when the results directory is created:
`results/<run ID>/`. The directory holds `manifest.json` with the commit of both
repositories, the dirty flags, package versions, input-file hashes, seeds,
parameters, the command line, and start and end times. Every run started for an
experiment additionally records its experiment ID in the manifest
(`manifest["experiment_id"]`), so the link is readable from either side.

### Algorithm ID

An arm's name alone does not pin what ran: the same name can mean different
code after a commit, and different behaviour under a different CLI flag with
the same code. The algorithm ID pins both.

* **`<arm>`** -- the arm name as it appears in the results
  (`fastener`, `fastener_guided`, `nsga2_obl`, `fs_sds`, ...).
* **`<code>`** -- the short (7-character) commit of the code that implements
  it. Two repositories are involved, so the form is
  `<experiments commit>+<fastener commit>`. For arms that do not touch the
  FASTENER clone, the second part is still given: it costs nothing and removes
  a question.
* **`<config>`** -- the first 4 hex digits of the SHA-256 of the arm's resolved
  configuration (budget, population, initialisation, k grid, row cap,
  classifier parameters), serialised as sorted JSON. It changes whenever a flag
  changes the arm's behaviour without a commit.

**A dirty working tree cannot produce evidence.** A run started with an
experiment ID is refused if either repository has uncommitted code. It can be
forced with `--allow-dirty` for diagnosis: every algorithm ID it issues then
carries the suffix `-dirty`, and its manifest says `evidence: false`. Such a
run may be used for diagnosis but not cited in a finding; commit first, then
run. This file, `HYPOTHESES.md` and any figure script count as code for this
purpose: the report must be reproducible from a commit, not from a working
tree. What does *not* count as code is what runs themselves write: `results/`,
`data/`, `experiments/reports/` and `experiments/EXPERIMENTS.md`
(`provenance.NON_CODE_PATHS`). Untracked files do count -- an uncommitted
module can be imported.

## The experiment ledger

[`EXPERIMENTS.md`](EXPERIMENTS.md) lists every experiment ID ever issued, one
row each, appended when the experiment starts -- not when it succeeds:

| experiment | hypothesis | started | run IDs | status | report |
|---|---|---|---|---|---|
| `H1-E01` | H1 | 2026-09-26 | `20260926T081500Z_h1` | reported | [report](reports/H1-E01/REPORT.md) |

Status is one of `running`, `failed` (did not finish), `invalid` (finished, but
a defect makes the result unusable -- the report says which), and `reported`.
A row is never deleted.

## The report

**Every experiment gets a report, including one that failed.** A failed
experiment's report is short, but it exists: what was attempted, what broke,
what was changed before the next attempt. The report is written before the next
experiment on the same hypothesis starts, so that what was learned from one
attempt is fixed before the next can overwrite it.

Location: `experiments/reports/<experiment ID>/REPORT.md`, with its figures in
`experiments/reports/<experiment ID>/figures/`. Reports and figures are
committed; the bulk run outputs stay in `results/` under the rules in
`.gitignore`.

**Generated first, then written.** The report skeleton -- header, the
hypothesis and criteria copied from `HYPOTHESES.md`, the per-seed tables, the
run facts, and every figure -- is generated from the run directories by script.
The summary, the description of what happened and the findings are then
written by hand on top of it. A number in the prose must match a number in a
generated table or figure; nothing is computed by hand.

### Structure

Sections in this order. None may be dropped; a section that has nothing to say
says so in one line.

#### 1. Header

| field | content |
|---|---|
| Experiment ID | `H1-E01` |
| Hypothesis ID | `H1` (for the joint experiment, `H2`, `H3`) |
| Run IDs | every run ID the report draws on, each with its status from the manifest |
| Algorithm IDs | one per arm, as defined above |
| Pre-registration | the commit of `HYPOTHESES.md` the hypothesis and criteria were taken from |
| Dates | run start and end (UTC), report date |
| Verdict | `supported`, `not supported`, `inconclusive` or `invalid` -- per hypothesis |

#### 2. Hypothesis

The claim, **quoted verbatim** from `HYPOTHESES.md` at the pre-registration
commit. Not paraphrased, not shortened: the report is judged against what was
written before the data existed.

#### 3. Evaluation criteria

Also quoted verbatim:

* the falsification criterion;
* the primary metric, with its K (AUF at K = 10 or K = 20) and the F1 average;
* the analysis the hypothesis prescribes (per-seed sign test, Wilcoxon with
  Holm correction, win/tie/loss counts);
* the secondary metrics that will be shown, labelled as secondary.

If any entry was revised after pre-registration, the revision's dated entry at
the bottom of `HYPOTHESES.md` is quoted too, with the reason.

#### 4. Summary

One paragraph, readable on its own: what was tested, on what, and the verdict
against the criterion, with the one number that decides it and its seed spread.
Anything surprising that a reader must not miss goes here as a second
paragraph.

#### 5. Description of the experiment

Detailed enough that a reader who has not seen the code can tell what was run,
and could spot a mistake in it. Two parts.

**Setup** -- what was intended:

* datasets, with row and feature counts after the row cap;
* arms, each with its algorithm ID and a plain-language description of what
  makes it differ from the others;
* seeds, budget, k grid, splits and classifier, and whether each matches the
  protocol table in `HYPOTHESES.md`;
* the command line of each run, from its manifest;
* **deviations from the protocol**, each with its reason. None is also an
  answer, and is stated as one.

**What happened** -- what actually ran:

* a timeline: runs started, finished, crashed, restarted;
* per arm, fits used and wall clock, and `stopped_on` -- whether each arm ended
  on the budget or on something else (convergence, an error, a time limit);
* runs that were missing, duplicated, or excluded, and why;
* anything anomalous seen during the run or in the progress snapshots -- a
  flat trajectory, a zero-byte log, an arm finishing in a fraction of the
  expected time -- whether or not it turned out to matter;
* for a failed or invalid experiment: the defect, how it was found, and what
  was changed before the next attempt, with the commit that changed it.

#### 6. Findings

Enumerated, **each supported by one figure**. A statement that no figure
shows is not a finding; it belongs in *What happened* or in *Open questions*.

Each finding has the same four parts:

```markdown
### Finding 1 -- nsga2_sparse reaches a higher AUF(K=10) than nsga2_obl on 5/5 seeds

**Claim.** One sentence, specific and falsifiable.

**Evidence.** The numbers behind the claim: per-seed values, the test statistic
and p-value where the criterion calls for one, effect size.

![Finding 1](figures/F1_auf10_per_seed.png)

*Figure 1.* What is plotted, on which axes, which split (validation or test),
and what the band or points show. Run IDs: `20260926T081500Z_h1`.

**Bearing on the hypothesis.** Whether this finding supports, contradicts or
is neutral to the claim, and why.
```

Rules for findings and their figures:

* **Finding 1 is always the verdict on the falsification criterion**, as it was
  pre-registered. Findings from 2 onwards are what else the data showed, and
  are marked **exploratory** when they test something not written down before
  the run.
* **Seed spread is shown on every figure** -- per-seed points or a min-max
  band. A mean is never plotted alone (*Analysis plan*, item 3).
* **Progress curves are plotted against cumulative fits**, with wall clock as
  a second view where it matters (*Progress tracking*).
* **Validation or test is stated on every figure.** Test-set progress curves
  are secondary and labelled so.
* Every figure is produced by a committed script from the run directories and
  carries the run IDs it was drawn from in its caption. File names are
  `F<n>_<short description>.png`, numbered as the findings are.
* A negative or null finding is reported with the same care as a positive one,
  and with a figure.

#### 7. Limitations and open questions

What this experiment cannot answer, given its seeds, datasets and budget
(*What 5 seeds can and cannot answer* in `HYPOTHESES.md`), and what it raised
that a later experiment or hypothesis should take up.

#### 8. Reproduction

The exact commands, from a clean checkout at the recorded commits, that
reproduce each run and regenerate every table and figure in the report.

## Workflow

```bash
# 1. Commit. Then issue the experiment ID; it is recorded as `running`.
python experiments/experiment_ids.py new H1            # -> H1-E01

# 2. Run, once per dataset, all under the same ID.
python experiments/run_sota.py --dataset eodata --experiment H1-E01 \
    --methods nsga2 --init sparse --no-fastener
python experiments/run_sota.py --dataset gina   --experiment H1-E01 ...

# 3. Generate the skeleton, then write the prose into REPORT.md.
python experiments/make_report.py --experiment H1-E01

# 4. Close the ID. It then accepts no further runs.
python experiments/experiment_ids.py status H1-E01 reported   # or failed / invalid

# 5. Log every decision the experiment ran under or led to in DECISIONS.md,
#    and add the experiment to its "By experiment" table.
```

The report generator reads the experiment's run IDs from the ledger, quotes the
hypothesis and criteria from `HYPOTHESES.md` at the commit of the first run,
and computes AUF from each front as `HYPOTHESES.md` defines it: at every k from
1 to K, the subset chosen on validation, scored on test, 0 below the smallest
subset. For H1-H3 it applies the paired rule (4 of 5 seeds, EOData and one
other development set); for H4-H6, per-dataset means, wins-ties-losses and
Wilcoxon with Holm correction. What it writes is a **mechanical reading** of
the criterion, placed next to the verdict, which is still stated by hand -- so
a harness defect that the mechanics cannot see can still overrule it.

## Before the first experiment

What the harness must do for the above to hold, checked against the code as it
stands.

| requirement | status |
|---|---|
| Run ID generated per invocation, with both repositories' commits and dirty flags | done -- `provenance.Run` |
| Experiment ID accepted by the runners and written to the manifest | done -- `run_sota.py --experiment`; `manifest["experiment_id"]` |
| Algorithm ID computed per arm and written to the manifest and to every result row | done -- `manifest["algorithms"]`, `algorithm_id` on every result, record and `comparison.csv` row |
| Runner refuses to tag a run with an experiment ID when either tree is dirty, unless forced for diagnosis | done -- `provenance.DirtyTreeError`; `--allow-dirty` |
| `EXPERIMENTS.md` ledger | done -- `experiment_ids.py`; the file is created when the first ID is issued |
| Report generator: skeleton, verbatim hypothesis and criteria, per-seed tables, run facts, figures | done -- `make_report.py`, except progress curves, which wait on per-iteration tracking (`HYPOTHESES.md`, *Before the first run*) |
| The other runners (`run_experiment.py`, `run_paper_replication.py`, `run_sota_experiment.py`) take `--experiment` | not needed yet -- every hypothesis runs through `run_sota.py` |
